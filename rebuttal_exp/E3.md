## 3. Part A 已有結果(誠實呈現,這是這一題的核心態度)

`rs( Bound_I on reference corpus, |dR| on benchmark )`,pooled over 全部 11 個 family × 5 benchmarks(55 cells):

| reference | mean rs | sd |
|---|---|---|
| same-benchmark(論文預設) | **+0.725** | 0.254 |
| wikitext(benchmark-independent) | **+0.506** | 0.254 |
| fineweb_edu(benchmark-independent) | +0.330 | 0.259 |

解讀與 rebuttal 框架(對應 Google Doc G3T9-W2 草稿的「state honestly whether rankings are preserved」):

1. **Generic reference 保留了大部分排序訊號但確有衰減**(0.725 → 0.506)。這不是 bug 而是特性:PRISM 的 bound 是 *input-conditioned* 診斷——「這個 variant 在這種輸入分佈上會退化多少」;拿掉輸入條件自然損失針對性。
2. wikitext 一致優於 fineweb_edu(fineweb 是 streaming 抽樣、domain 更雜)。建議 rebuttal 引 wikitext 數字。
3. per-family 表在輸出檔中;主文 2×5 grid 的兩個 family 單獨引用時請從該檔取值(例:Qwen3-8B 的 triviaqa/gsm8k cells 在 generic reference 下轉負——與 GSM8K 既有的 CE-decoupling 限制一致,pCi8-W4 的敘事可交叉引用)。

## 4. Part B / C 設計

**Part B(診斷端 size)**:對 Llama 全 12 variants,各 size 抽 wikitext 特徵、重算 Bound_I(理論 K 用 target head),對既有 benchmark `|MdR|` 算 rs。輸出 size × benchmark 的 rs 矩陣 → 填 G3T9-W2 草稿的 `{8,16,32,64,128} → [XX/XX/XX/XX/XX], stabilizing at [N]`。
每個 variant 一次載入、5 個 size 順跑(≤128 序列的 forward 是秒級,成本全在載入)。

**Part C(regularizer 端)**:`train_forgetting_baselines.py --method trace --ref_task {truthfulqa|wikitext} --reg_samples {8,32,128}`(**λ=0.5** = llama 唯一有完整 step-300 anchor 的 operating point;lr 用已修正的 1e-5 預設;reg_every_k=8 預設,**配對樹 λ0.5 TQA 的 k=8**;**每 config 專屬 output_root**),輸出與論文同 schema 的 JSON → 比 retention 差異 → 填 8VrD-Q3 草稿的 `changes retention by at most [XX]%`。

兩個附註:(1) **(task, 32) config = 樹 λ0.5 TQA 的同 seed 同協議重跑**——12 個 checkpoint 全程可比,是比 E2 backfill(6 點)更長的環境 canary,免費附贈。(2) **論文正文 L344 說 ref 是 "32 pre-training sequences",但程式碼實作是 FT 任務的 test split(seed+1000)**——正文措辭錯誤;rebuttal 描述 ref set 時**以程式碼為準、勿引正文那句**,revision 勘誤 Sec 5.4。

## 7. 首輪 postmortem(2026-07-24 run,三個 bug,均已修)

1. **Part B OOM**:`compute_all` 內建的 spectral SVD(4096×128k,~4.1 GiB workspace)在 8B proxy 尚駐留 GPU 時執行 → 32 GB 卡爆。**修法**:先收集所有 size 的特徵、釋放模型,再用輕量 Bound_I primitives(`rms_scale`/`trace_omega`/`feature_error`/`head_discrepancy_covariance`)計算——spectral 本來就不進 bound。同型修正已套用到 **E4、E11**(E9 原本就安全)。
2. **Part C 輸出互相覆寫**:trainer 的目錄結構不含 `ref_task`/`reg_samples`,六個 config 寫同一路徑,只剩最後一個 JSON。**修法**:`script_E3.sh` 改為每 config 專屬 `--output_root`。六個 config 的 step-300 數據已從 screen log 完整回收(`exp_e3_partc_from_log.py` → `out/E3/partC_summary.md`,與倖存 JSON cross-check MATCH)。
3. **lr 協議錯誤(最重大)**:首輪以 baselines 舊預設 lr=2e-4 跑;但 paper-round 全部 run 實為 `--lr 1e-5`(JSON 可證)。2e-4 使軌跡自 step 50 起偏離論文 4×,(task,32) 同 seed 重跑無法重現 anchor。**修法**:baselines 預設改 1e-5;首輪六個數字標為 lr-stress 內參,**不得引用**;λ 同時從 1.0 改 0.5(唯一有完整 anchor 的 operating point;舊「λ1.0→0.618」是中斷 run 的 step-150 誤讀,見 E2.md §4 勘誤)。

## 8. 結果(2026-07-26 定稿;Part B 診斷側 size + Part C regularizer 側 size×domain)

### 8.1 Part B — 診斷端 size ablation(G3T9-W2 / AC-B 樣本效率)

Llama 全 12 variants,wikitext 參考,size {8,16,32,64,128} × 3 draws(seed 42 / 1042 / 2042),
**current full-feature pipeline**。結論:**變體排序對參考大小與抽樣完全不敏感**。

- bound_I 值本身隨 size/draw 抖動 **~11% CV**(非 ±5%;已驗非 loader bug,n_tokens
  正確隨 size 變:size8 draws 717/454/176、size128 8095/9510/8330)。
- **機制 = common-mode noise(重要,勿用「40× spread」的錯誤說法)**:12 個 variant
  雖然整體跨 ~40×,但**相鄰**變體只差 ~5(FP4 vs Q3_K_M,envelope 甚至跨 combo 重疊
  122–131 vs 127–137)。排序不翻轉**不是**因為間距大,而是因為**所有 variant 共用同一份
  抽樣 reference**,小/歹運抽樣讓大家的 bound **一起同向平移**,pairwise 次序因此保留。
  已驗:15 個 (size,draw) combo 的**完整排序唯一**(distinct ordering = 1);最接近的一對
  FP4/Q3_K_M 在全部 15 combo 內 FP4 恆 < Q3_K_M(從不翻)。
- 因此 rs(bound_I, |dR|) 逐 benchmark **在所有 size 與所有 draw 下四位小數完全相同**
  (arc +0.9441 / mmlu +0.9441 / squad +0.8112 / tqa +0.9650 / gsm8k +0.9650;mean +0.926),
  distinct=1。8 條序列即重現全量排序 ⇒ 論文的 32 條綽綽有餘、非幸運抽樣。
- **貼文用法**:別丟「大數值 wiggle、次序不變」的天真表(會被 reviewer 抓 envelope 重疊
  → 質疑「會不會 swap」);要丟**最接近一對跨 draw 不翻**的小表(closest-pair,common-mode
  框架),把「會 swap?」變成自證。FP4/Q3_K_M 跨 draw 表:
  n8 draw0/1/2 = 126.6/124.4/123.4 vs 132.0/127.0/131.2;n128 = 130.0/128.2/129.4 vs
  134.8/133.0/134.9(FP4 恆 <)。

### 8.2 Part C — regularizer 端 size×domain(8VrD-Q3 / AC-B),全部 lr=1e-5 ✅

trace λ=0.5、Llama-TruthfulQA、k=8、seed 42、300 steps,**lr=1e-05 全部確認**
(舊 partC_summary 的 lr=2e-4 六格維持「INTERNAL ONLY 勿引」)。no-reg(λ=0)mean downstream
|dR| = **1.4830**(lr=1e-5)。

| reference | size | mean downstream |dR| | vs no-reg | mean Ω |
|---|---|---|---|---|
| task(TruthfulQA)| 8 | 0.7252 | **−51.1%** | 0.923 |
| task | 32(論文 tree anchor)| 0.7357 | −50.4% | 0.924 |
| task | 128 | 0.7243 | −51.2% | 0.925 |
| wikitext | 32 | 0.7731 | −47.9% | 0.915 |

結論(誠實且有利):
1. **Size 不敏感**:task 域 8/32/128 = −51.1% / −50.4% / −51.2%,幾乎持平;**8 條就給滿效益**。
2. **Domain 輕度敏感但穩健**:n=32 時 task(−50.4%)vs generic wikitext(−47.9%),wikitext 只差
   ~2.5 個百分點,仍大幅降遺忘 ⇒ **regularizer 不需要 in-task 資料**。
3. 四格全部把 Ω 從 no-reg 的 0.83 拉到 ~0.92。
4. 「retention 隨設定最多變多少」:降幅落在 **[−47.9%, −51.2%]**(mean |dR| ∈ [0.724, 0.773]),
   即跨 size×domain 最多差 ~3.3 個百分點。

### 8.4 ⚠️ 勘誤:§8.2/§8.3 的 anchor 拿錯了(2026-07-29,E15 追出來)
