## 2. 可行性結論:**可行,~2–2.5 h(Llama family,N=100)**

Gemini 建議的「MMLU 100 題」規模正確;實作上有兩個它沒處理的關鍵設計已解決:

1. **Trajectory 的定義**:free-run 的重點是 *proxy 的錯誤累積進自己的 context*(8VrD 原話)。協議:**proxy 對每個 prompt greedy 生成延續;target 與 proxy 都在「proxy 自己生成的軌跡」上抽特徵與算 per-token CE**(生成區域)——feature rows 仍然逐 token 對齊(同一段文字),但該文字承載了 proxy 的 compounding drift。同時在同 100 題的 gold 序列上算 teacher-forced 版本作 apples-to-apples 錨點。
2. **單卡記憶體**:target 常駐 CPU RAM,每個 proxy 釋放後才搬上 GPU——無雙模型 VRAM 壓力、無特徵落地磁碟。

成本:每 variant ≈ 8–12 min(載入 + 100×128 token greedy 生成 + 三趟抽取)× ~12 variants ≈ **2–2.5 h**。

## 3. 輸出與 rebuttal 用法

`out/E7/E7_results_{family}_{dataset}.md` 四個數字:

- `rs(B, |ΔR|)` teacher-forced(同子集)vs **free-running** ——主結果,填 AC-D 與 8VrD-W4 的 [XX]
- `rs(B_tf, B_free)` rank agreement——bound 排序在兩種協議下是否一致
- cross `rs(B_tf, |ΔR|_free)`——teacher-forced bound 能否預測 free-run 退化(實務上最有用的一格)

Rebuttal 句型(AC-D):

> On a [100-prompt MMLU] subset, we recompute PRISM on each variant's own greedy continuations (so surrogate errors compound into its own context): rs(B,|dR|) is [XX] free-running vs [XX] teacher-forced, with bound-rank agreement [XX]. Independently, we have restated Corollary 1 as teacher-forced-only and added trajectory-distribution shift as an explicit limitation — the bound itself applies to any feature matrix pair "whatever the origin of the rows" (App. D), so this is a protocol scope, not a theoretical one.

失敗備案(AC 明文接受):只保留第二句(claim narrowing)。

## 4. 設計細節與風險

- greedy(do_sample=False)確保可重現;`max_new_tokens=128` 可調。
- 生成 0 token 的樣本(立即 eos)自動剔除並計數。
- head 慣例與論文一致:只有 GGUF 的 H_P 用反量化權重;BnB/GPTQ/dtype 視為 head 保留(γ≡0)。
- 風險:free-run |ΔR| 的動態範圍可能比 teacher-forced 小(所有 variant 生成的都是「自己舒服的」文字)→ 若 rs 降低,誠實報告並用 rank-agreement 欄支撐「bound 排序穩定」的較弱主張;劃界句無論如何都上。
