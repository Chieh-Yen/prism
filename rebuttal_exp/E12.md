## 2. 可行性結論:**無獨立 GPU 成本**(搭 E1/E7 的便車 + CPU 計數)

三個成份,全部同一台 5090:

| 成份 | 來源 | 性質 |
|---|---|---|
| PRISM 每 variant 成本(load + 5-benchmark 單趟 forward) | **E1 log 實測**(`[load]`/per-bench 秒數,已埋在 exp_e1) | measured |
| Greedy decode throughput(tok/s) | **E7 log 實測**(`[gen]` 行,已埋在 exp_e7) | measured |
| Benchmark suite 必須「生成」的 token 量 | 論文同 split 的 answer/CoT span tokenize 計數(CPU) | counted |

Benchmark 端估計 = Σ_b n_b × mean_answer_tokens_b ÷ throughput,是**刻意的下界**
(greedy、單 pass、無 retry/self-consistency,且還沒算 scoring 需要標籤)——
往對我們不利的方向保守,rebuttal 中明說。

## 3. 執行順序(依賴 E1、E7 先跑完)

```bash
bash rebuttal_exp/script_E1.sh      # 產生 [load]/per-bench 計時
bash rebuttal_exp/script_E7.sh      # 產生 [gen] tok/s
python3 rebuttal_exp/exp_e12_cost_table.py   # 彙整(CPU,分鐘級)
```

輸出:`out/E12/cost_table.md` — 每 variant:load 分鐘 / PRISM 5-benchmark 抽取分鐘 /
PRISM 總分鐘 vs benchmark decode 估計分鐘 + 摘要句(含 screening-mode 32-seq 折算)。

## 4. Rebuttal 用法(G3T9-W1 的 [TBD-E12])

> PRISM ranks a new variant with ONE teacher-forced forward pass per benchmark
> over the reference set — measured [X] min/variant on an RTX 5090, no labels,
> no decoding — vs a conservative lower bound of [Y] min/variant merely to
> DECODE the same 5-benchmark suite once at our measured [R] tok/s (greedy,
> single pass; scoring additionally requires labels). Screening mode
> (32-sequence generic reference) is ~16x cheaper again and load-dominated.

| 風險 | 處理 |
|---|---|
