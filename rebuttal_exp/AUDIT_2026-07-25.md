## 七、E3 首輪 postmortem(2026-07-25 補記,重大)

E3 於 GPU 機首輪執行(07-24)後分析發現三個 bug,均已修復;**E2 連帶受影響**:

1. **Part B OOM**:`compute_all` 的 spectral SVD(4096×128k)在 8B proxy 駐留 GPU 時執行 → 32 GB 爆。修:先收特徵、釋放模型,再用輕量 Bound_I primitives。同型修正套用至 **E4、E11**。
2. **Part C 輸出覆寫**:六個 (ref, size) config 寫同一目錄,只剩最後一個 JSON。修:per-config `--output_root`。六個 config 的 step-300 數據已從 screen log 完整回收(`exp_e3_partc_from_log.py`,與倖存 JSON cross-check MATCH)→ `out/E3/partC_summary.md`(**lr-stress 內參,不得引用**)。
3. **lr 協議錯誤(最重大)**:baselines 繼承 multitask 腳本的 lr 預設規則(llama 2e-4),但 **paper-round 全部 run 實以 `--lr 1e-5` 啟動**(樹 JSON `experiment.lr` 可證)。2e-4 使軌跡 step 50 起偏離論文 4×。修:`train_forgetting_baselines.py` 預設 lr=1e-5、reg_batch_size=8。**首輪 E3-C 六個 run 與任何已跑的 E2 sweep(lr 2e-4)一律作廢重跑**。
4. **連帶勘誤**:E2.md 舊 anchor「trace λ1.0 → 0.618 @step300」為誤讀——該 run 中斷於 step 150,0.618 是 step-150 值;λ1.0 無完整 anchor。llama trace anchor 改 **λ0.5 = 0.7357 @300(−50.4%,與 E10 b%@0.5 吻合)**;script_E2.sh seeds/qwen 階段與 script_E3.sh part C 的 λ 均已改 0.5。
5. **時程修正**:E3-C 重跑 ~9 h(wikitext-ref 的 reg forward 讓每 run ~1.5 h,非原估 25 min);E3 合計 ~10 h。
