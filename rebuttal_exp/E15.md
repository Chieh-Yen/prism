# E15 — Reference set 的 **paired** draw ablation(regularizer 端;8VrD-Q3)

## 1. 為什麼要新開一個編號,而不是補 E3 Part C

E3-C 已經有四格(task 8/32/128 + wikitext 32),但「**domain 影響不大**」這個結論靠的是
`0.7358 (task,32)` vs `0.7731 (wikitext,32)`,而這組對比**同時動了三件事**,
所以那 0.04 nats 不能歸因給 domain:

| 混淆軸 | task(TruthfulQA)| wikitext |
|---|---|---|
| **item 種類** | 有 `formatter` + `prompt_formatter` → batch 帶 `prompt_length`,`loss_mode=answer` | 純 raw text,**沒有 prompt 邊界**,`loss_mode=full` |
| **實際交付大小** | 32 條 | **19 條**(`TextDataset` 在 select 之後才丟空白行;wikitext-2-raw test 大量空行與 ` = Header = `)|
| **token 預算** | 851 tokens(gpt2 計) | **1803 tokens**,2.1× |
| **同條件內的尺度** | 每格只有 1 run,0.04 nats 是大還是落在 run-to-run 噪音裡,**無從判斷** |

(「19 條 / 1803 tokens」不是估計,是 `--preflight` 用 trainer 同一條 code path 真的把
reference set 建出來數的;見 §5。序列數與 overlap 與 tokenizer 無關,token 數會隨 tokenizer 變。)

E15 把被操作的變數**移進論文自己的 setting**:同樣是任務自己的 test split、同樣 n=32、
同樣 formatter 與 prompt 邊界,**只換是哪 32 條**,而且是同一次 shuffle 的**互斥視窗**。

## 2. Anchor:draw 0 就是論文那一格(免費)

論文輪的權威樹是 **`regularization_exp/exp_result/`**(post-gradient-fix sweep),
全部 lr 1e-5、seed 42、n_ref 32、k=8、max_steps 300、`meta-llama/Llama-3.1-8B`,
逐 benchmark 與 `paper/exp_replay_trace.md` §4 的 Table-2 dump 完全吻合:

| λ(trace)| mean downstream \|dR\| @300 | mean Ω | target loss_P |
|---|---|---|---|
| **0(no reg)** | **0.8434** | 0.9063 | 0.9169 |
| 0.01 | 0.8004 | 0.9128 | 0.8702 |
| 0.05 | 0.7757 | 0.9155 | 0.8716 |
| 0.1 | 0.7603 | 0.9172 | 0.8656 |
| **0.5** | **0.7358** | 0.9242 | 0.8537 |
| **1.0 ←論文 Table 2** | **0.6813** | 0.9310 | 0.8423 |

Table 2 caption 的三個數 `0.843 / 0.764 / 0.681`(no reg / replay λ0.01 / **trace λ1.0**)
就是這張表 → **E15 預設 λ=1.0**,draw 0 = 0.6813 免費,結果可直接貼在 Table 2 旁邊。
`LAMBDA=0.5` 則對齊 E3-C 的 size 軸(0.7358)。

> 用正確 anchor:λ0.5 = **−12.8%**、λ1.0 = **−19.2%**(= 論文的 −19% ✓),數字自洽,
> **E3-C 與論文本來就同輪、可以直接比**。E15 的彙整器已改抓 0.8434,若 fallback 到
> 1.4830 會在標題印 `SUPERSEDED BASELINE` 警告。

## 3. 設計(單一操作變數 = paired 的定義)

| 固定 | 值 |
|---|---|
| model / task | `meta-llama/Llama-3.1-8B` / truthfulqa(**與論文樹同一個 repo 字串**,不用 E3-C 的 Meta- alias)|
| method / λ / lr | trace / **1.0**(預設)/ 1e-5 |
| seed / steps / save_steps | 42 / 300 / 25 |
| reg_samples / reg_every_k / reg_batch_size | 32 / 8 / 8 |
| reference pool | 任務自己的 test split(`validation[80%:]` = **163 列**),shuffle seed **1042** |

| 被操作 | cells |
|---|---|
| **哪 32 條** | offset **0**(=論文,免費)、**32**、**64**、**96**;spare = **128** |
| **無**(floor)| offset **0** 的 replicate(`:rep` 後綴另開目錄)|

163 列 → 最多 5 個互斥視窗(0/32/64/96/128,用到第 159 列);`offset+n > 163` 會在 loader
直接 raise,不會靜默 wrap。

**replicate 為什麼必要(不只是量噪音)**:draw 0 是 `train_forgetting_multitask.py` 跑的,
E15 的 draws 走 `train_forgetting_baselines.py`。若把兩者混在一起算 sd,就把 **script path 差異**
折進 draw 的變異裡。所以:
- **paired set = 全部走 baselines script 的四格** = `off0:rep`(draw 0)+ off32/64/96 → 這組算 mean±sd。
- **論文樹的 0.6813** 當 **reproduction canary**:`|off0:rep − 0.6813|` = 非決定性 + script path,
  是 draw 效應的**保守 floor**。

**cell 順序 = 證據價值順序**(時間不夠時砍尾巴):
`off32` → `off64` → `off0:rep` → `off96`。跑完 2 格就有 3 點 spread(含 anchor),
跑完 3 格 spread 才有量到的 floor,第 4 格收緊 sd。

## 4. 成本(**實測**,單張 RTX 5090)

論文輪自己的 log 就寫明 all on RTX 5090,300-step run 的 tqdm 收尾為
1:11:07 / 1:15:00 / 1:15:21 / 1:29:29;E3 的 λ0.5 重跑(同協議)為
**n=8 → 1:13:59、n=32(wikitext,19 條)→ 1:24:17、n=128 → 1:28:51**,
shell 端間隔(含 load + base-feature precompute)分別 75.8 / 85.9 / 90.6 min。

| n_ref | 每 cell wall clock | 4 cells(3 draws + replicate)|
|---|---|---|
| 8 | ~74 min | **~4.9 h** |
| **32** | **~79 min** | **~5.3 h** |
| 128 | ~89 min | ~5.9 h |

Part 0(preflight)與 Part Z(彙整)都是 **0 GPU、秒級**。
只跑 Part 0 + 前兩格 ≈ **2.7 h** 就能講「同 size 不同 draw 差 X nats」,但**沒有 floor**,
只能當上界報。

## 5. seed 呢?

**預設是單一 training seed 42、四個 reference draws,不是三個 seed。** 這是刻意的:
E15 問的是「換 reference」,seed 變異在 **E2 的三 seed 表**(那張表報 0.680 ± 0.016)。
兩者不要合成一個 ± 值。

真要 seed × draw 交叉:`SEED=43 REF_SEED=1042` 可讓 reference 固定、只換訓練 seed;
3 seeds × 4 draws = **12 runs ≈ 16 h**,而且分析要當 two-way 看(draw 效應 vs seed 效應),
本輪不建議。

## 6. size ladder:32 → 16 → 8(每個 size 一個 block,各 4 cells)

163 列 pool 能切出的**互斥**視窗數,與每個 block 的實測成本:

| n | 互斥視窗 | offset-0 anchor | 每 cell | block(4 cells)|
|---|---|---|---|---|
| **32** | 5(0/32/64/96/128)| **免費**(論文 reference size)| ~79 min | **~5.3 h** |
| **16** | 10 | 無,要自己跑 offset 0 | ~76 min | **~5.1 h** |
| **8** | 20 | 無(E3-C 的 n=8 是 λ0.5 + Meta- alias,不同格)| ~74 min | **~4.9 h** |
| 128 | **1** | — | ~89 min | **互斥 draw 不可能**;次佳 offset 35 與 offset 0 共用 **93/128 列**(73% overlap),要跑必須明寫 overlap |

三個 size 全跑 = **12 runs ≈ 15.3 h**;每 size 砍到 3 draws = 9 runs ≈ 11.5 h。
**floor 只需在 n=32 block 量一次**(它是 pipeline 性質,不隨 n 變),16 / 8 直接沿用,
所以那兩個 block 的 4 格全部是真 draws。

```bash
N=32 E15_CELLS="truthfulqa:32:32 truthfulqa:32:64 truthfulqa:32:0:rep truthfulqa:32:96" \
     bash rebuttal_exp/script_E15.sh
N=16 E15_CELLS="truthfulqa:16:0 truthfulqa:16:16 truthfulqa:16:32 truthfulqa:16:48" \
     bash rebuttal_exp/script_E15.sh
N=8  E15_CELLS="truthfulqa:8:0 truthfulqa:8:8 truthfulqa:8:16 truthfulqa:8:24" \
     bash rebuttal_exp/script_E15.sh
```

跑完是一張 **3 sizes × 4 draws 的 λ=1.0 網格**:size 軸與 draw 軸同時回答,
且全部對得上論文 Table 2 的 0.6813。這會取代 E3-C 那條 λ=0.5 的 size 軸
(E3-C 仍可留作獨立佐證)。

## 6b. 中斷續跑

| 情況 | 行為 |
|---|---|
| cell 已有 step-300 json | `script_E15.sh` 直接 SKIP |
| cell 跑到一半死掉 | `--resume auto`(預設)從 **metrics json 覆蓋到的最新 checkpoint** 續跑,並保留先前的 PRISM 記錄 |
| 同一個 output_root 裡是**別的 config** | **直接 abort** 並印出哪個欄位不符,不會混寫 |

兩個細節:HF 是**先寫 checkpoint 目錄、再跑 callback 的 PRISM eval**,所以若死在 eval 中間,
目錄比 json 新;續跑會退回 json 覆蓋到的那一格(多跑 25 步,但記錄不留洞)。
`save_total_limit=2` 只留最後兩個目錄,所以續跑最多回退 ~50 步 ≈ 13 min。

## 7. 執行

```bash
PARTS=0 bash rebuttal_exp/script_E15.sh          # preflight,任何機器
bash rebuttal_exp/script_E15.sh                  # 0 + A + Z(GPU 機),λ=1.0
LAMBDA=0.5 bash rebuttal_exp/script_E15.sh       # 對齊 E3-C 的 size 軸
PARTS=Z bash rebuttal_exp/script_E15.sh          # 只重算表
E15_CELLS="truthfulqa:32:32 truthfulqa:32:64" bash rebuttal_exp/script_E15.sh   # 砍到 2 格
```

Part 0 用 `--tokenizer "$MODEL"`(要能取到該模型的 tokenizer;本機若只 cache 了
`tokenizer.json` 會失敗,GPU 機正常)。想在沒有 gated 權限的機器先看互斥性,
加 `--tokenizer gpt2` —— 序列數與 overlap 不受影響,只有 token 兩欄會變。
目前 repo 內的 `out/E15/preflight_refsets.md` 就是 gpt2 版(標頭已標明),
GPU 機跑 Part 0 會覆寫成 Llama 版。

已完成的 cell(有 step-300 json)在重進時自動 SKIP。
⚠️ `script_E3.sh` 的同型 gate 找的是 `prism_forgetting_metrics_<task>.json`(論文樹命名),
而 baselines trainer 實際寫的是 `prism_forgetting_metrics.json` → E3 的 skip **從來沒生效過**;
E15 的 gate 已用正確檔名。

## 8. 框架改動(3 處,都是 backward-compatible)

| 檔案 | 改動 | 相容性 |
|---|---|---|
| `prism/data/loaders.py` | `load_task_data(..., offset=0)`:shuffle 後取 `[offset, offset+n)`;streaming task 或超出 pool 皆 raise | `offset=0` 與舊行為**逐 token 相同**(已用 `torch.equal` 驗),E1D/E14 依賴的 8⊂32⊂128⊂512 nesting 不變 |
| `rebuttal_exp/train_forgetting_baselines.py` | 新增 `--ref_seed`(預設 `seed+1000`)、`--ref_offset`(預設 0);兩者寫進 `experiment` block;印出 requested vs **kept**,少於 requested 就 warn | 不給旗標時與論文協議完全一致 |
| `rebuttal_exp/train_forgetting_baselines.py` | 新增 `--resume auto\|no`(預設 auto):`plan_resume()` 找 checkpoint、比對 12 個 config 欄位、把舊 PRISM 記錄餵回 callback 再 `trainer.train(resume_from_checkpoint=...)` | 目錄乾淨時行為不變;config 不符會 abort(callback 每次是**整檔覆寫**,不餵回舊記錄就會把 json 截成續跑後的尾巴)|
| — | `--ref_seed` 是 paired 的關鍵:reference draw 從此**與 training seed 解耦** | 沒有它,想換 reference 只能換 `--seed`,那會連 LoRA init 與 data order 一起換掉 = unpaired |

## 9. 輸出

- `out/E15/preflight_refsets.md` — 交付大小、token 數、prompt 邊界、set fingerprint、**pairwise overlap 矩陣**(對角外全 0 = DISJOINT),外加 wikitext 那格的不對等數字。
- `out/E15/refdraw_summary.{md,csv}` — 每 draw 的 mean downstream |dR| / mean Ω / target loss_P / 逐 benchmark |dR|;走同一 script path 的 draws 的 **mean ± sd、CV、range**;replicate 對照論文樹的 **floor** 與 `spread / floor` 比。
  彙整器內建 **protocol guard**:cells 的 lr / λ / reg_samples 只要不一致就在標題印
  `MIXED PROTOCOL, DO NOT POOL`(E3-C 首輪 lr=2e-4 混用的那個坑),no-reg anchor 抓到舊 1.4830 也會警告。

## 10. 兩種結果都能寫

| 結果 | 貼文寫法 |
|---|---|
| spread ≲ floor(預期)| 「在論文的 setting 內(λ=1.0,即 Table 2 那一格),把 D_ref 換成任務自己 test split 的**另一組互斥 32 條**,downstream gap 只動 X ± Y nats,與**固定 reference 重跑同一個 config 的差距同量級**(floor = Z)⇒ 具體是哪 32 條不是 knob。」比原本的 wikitext 對比強,因為沒把 domain / item kind / token 預算綁在一起。 |

## 11. 與 E3 的分工(勿混用)

- E3-C 的 **size** 軸(8/32/128 = 0.725/0.736/0.724 @λ0.5)繼續引用;它與論文同輪,
  對 0.8434 算的降幅是 −14.0% / −12.8% / −14.1%。
- E3-C 的 **wikitext** 格:改為「這是 unpaired 對比」的**上下文**,`preflight_refsets.md`
  提供它到底不對等在哪(19 vs 32 條、2.1× tokens、無 prompt 邊界)。要主張「不需要 in-task
  資料」時,引它請一併標明這三個混淆軸——或改引 E15 的 paired 結論,只講「draw 不 load-bearing」。
- 若之後要一個 **paired 的 domain 對比**:換成同樣有 formatter + prompt boundary、
  且**不在** downstream eval 集(arc/mmlu/squad/triviaqa/gsm8k)內的結構化任務,
  例如 `social_iqa` 或 `lima`(`E15_CELLS="social_iqa:32:0 lima:32:0"` 即可跑),
  這樣才是只動 domain。**本輪不含**,因為 8VrD-Q3 問的是 32 這個 size 與 reference 選擇。

## 12. 已知 caveat

1. **ref ⊂ target-task eval pool**:reference 抽自 `validation[80%:]`,而 target-task 的 PRISM
   eval 也是這個 split(論文既有協議,未改動)。四個 draw 都在同一個 pool、target eval 都是整個
   pool,所以對 draw 比較是**對稱的**;但描述 reference set 時不要說它與 eval 無關。
   (另:論文正文 L344 寫 ref 是 "32 pre-training sequences",與程式碼不符 —— E3.md §4 已記,
   revision 勘誤 Sec 5.4。)
2. **單一 seed**:見 §5。
3. **token 預算殘餘不齊**:32 條固定,但 token 數在 draw 間仍有 ~8% 的差(preflight 有數字)。
   這是 paired 設計裡誠實留下的殘差,spread 要對著它讀。
4. **repo 裡已有一組同 config 的重複**:`regularization_exp/.../0.5/llama` 與
   `exp_result/regularization/0.5/llama` 同 seed 同設定,mean 0.7358 vs 0.7357(Δ 0.0001),
   但逐 benchmark 可差到 0.008(mmlu 0.1103 vs 0.1023)⇒ mean 上的 run-to-run floor 很小,
   per-benchmark 不小。**別**用這一對取代 replicate cell(來源不完全確定),但它預示
   floor 量級。
