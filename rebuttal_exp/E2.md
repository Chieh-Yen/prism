### 對 Gemini 建議的兩點修正(重要,避免誤配預算)

- Gemini:「EWC 算 Fisher 極慢且易 OOM,只能跑縮水版(batch 1、單 seed、單任務)」——**不適用於本實作**:我們的 Fisher 只對 LoRA trainable 參數(~數十 M)累積,記憶體開銷數十 MB、一趟 32 條 ref 序列即完成,**無 OOM 風險**,完整跑 2 tasks × 3 λ × 3 seeds 沒有問題。
- Gemini:「放棄 feature-KD(易 OOM)」——前提錯誤:feature_kd 與論文已在跑的 trace regularizer **共用同一 ref-forward 機制**,成本相同;且 G3T9-W3 原文就點名 "simpler feature-preserving regularizers",砍它等於留一個口。保留,sweep 順位最後。

### 取捨(明確列出、rebuttal 中可辯護)

1. **sweep 只在 Llama-3.1-8B**;Qwen 只在 best 設定複製(選配 stage)。理由:與論文 main(Llama)/appendix(Qwen replication)的結構一致。
2. **EWC 實作為 LoRA trainable 參數上的 diagonal Fisher**(non-degenerate 說明見 §3)。不做全權重 Fisher(≈14 GB fp16,非 PEFT 文獻慣例)。
3. **每方法 3 個掃描點**:layer_freeze K∈{4,8,16};l2sp/ewc λ∈{1e-4,1e-3,1e-2};feature_kd λ∈{0.1,1,10}。Fisher 正規化到 unit mean,使 ewc 與 l2sp 共用同一 λ 尺度。
4. **3 seeds 只在 best 設定**(sweep 單 seed)——與論文自己的 sweep 協議一致("each at its sweep |ΔR|-best")。
5. **SLoRA / two-phase / CLAIM / ArMA(8VrD 列的四篇 2026)不在 rebuttal 內重跑**:皆為 sequential/continual instruction tuning 設定,與本文單任務 forgetting 協議不同;AC-C 的 "or layer-freezing/replay variants" 措辭正好給了低成本合規路徑——已實作 layer-freezing,四篇在 Related Work 討論 + revision 承諾比對 setting 相符者。

## 3. 方法定義(`train_forgetting_baselines.py`)

懲罰型 trainer 都繼承論文的 `ShapeRegularizedTrainer`,**完全沿用其排程與 backward 路徑**(每 optimizer step 一次、獨立於 grad-accum 除法),只換 loss 泛函——與 trace/replay 嚴格 apples-to-apples:

| method | 懲罰項 / 機制 | 空間 |
|---|---|---|
| `layer_freeze` | 無懲罰項;LoRA 只掛 top-K 層(`layers_to_transform`),底層完全凍結 | architecture(AC 點名) |
| `l2sp` | λ · Σ‖θ − θ₀‖²(LoRA 參數) | parameter |
| `ewc` | λ · Σ Fᵢ(θᵢ − θ₀ᵢ)²,F = ref set 上的 diagonal empirical Fisher(unit-mean 正規化) | parameter(Fisher 加權) |
| `feature_kd` | λ · ‖Z_t − Z₀‖²_F / ‖Z₀‖²_F(同一組 32 ref 序列) | feature |

`layer_freeze` 的輸出目錄以 `top{K}` 取代 `lam{λ}`,aggregator 已同步支援。

**EWC 的 B=0 說明(要寫進 rebuttal/appendix,先講清楚避免被抓)**:Fisher 在 adapter 初始化點估計——此時模型恰等於 base model,即 pre-training「舊任務」的 optimum,是 EWC 教科書上正確的估計點。該點上 lora_B=0 ⇒ ∂ℓ/∂A=0,Fisher 質量集中在 lora_B——這是 EWC-on-LoRA-parameters 的固有性質(PEFT continual-learning 文獻的標準做法),腳本會印出 nonzero 比例供檢查。

其餘 protocol 與論文逐項相同:LoRA r=32/α=64/dropout .05、同 7 個 target modules、batch 2×8、cosine、warmup 5%、bf16、300 steps、ckpt/eval 每 25 步、ref set = 同任務 test split 32 條(seed+1000)、`PRISMCheckpointCallback` 輸出同 schema 的 JSON。

**Target-task 指標免費取得**:callback 的 eval 任務清單首位就是 FT 任務本身,`loss_P`(answer-only)即 target-task 表現 → 一張表同時填 eQL6-W4 與 8VrD 的 source-task 要求。
