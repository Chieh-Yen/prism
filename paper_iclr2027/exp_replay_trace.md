# PRISM Regularization Experiment: Trace Norm vs Replay (Updated)

> **目的**：分析新跑的 trace norm + replay regularization 實驗（gradient bug 修正後 + 擴增 λ sweep），建議「弱 replay + 強 trace norm」的呈現方式 + 故事。
>
> **數據設定**：
> - **Trace norm**：`regularization_exp/exp_result/regularization/{0.01, 0.05, 0.1, 0.5, 1.0}/{llama,qwen}/`
> - **Replay**：`regularization_exp/exp_result/regularization_replay/{0.0, 0.001, 0.005, 0.01, 0.05, 0.1}/{llama,qwen}/`
> - **Baseline λ=0** 從 `regularization_replay/0.0/` 取（與 gradient fix 一致；user confirmed: replay 0 = trace 0 = 原本實驗 0）
> - 兩 method 都用 32-sample reference set，`reg_every_k=8`（gradient bug 已修）
> - LoRA config：`r=32, α=64, dropout=0.05, lr=1e-5, batch_size=2, grad_accum=8`，all on RTX 5090
> - All metrics 取自 step 300

## 3. Defense vs Reviewer Question

### 3.1 「為何不挑 trace 跟 replay 各自的 sweep best？」

**Answer**：替代方案中 trace 仍贏，且 1× scale + clean 的 1-order-of-magnitude pair 更易解讀：

| Pair | Llama TruthQA \|ΔR\| | Llama BBQ Ω |
|---|---|---|
| Replay 0.01 (best for TQA) vs Trace 1.0 | 0.764 vs **0.681** | 0.934 vs **0.983** |
| Replay 0.1 (best for BBQ) vs Trace 1.0 | 0.789 vs **0.681** | 0.915 vs **0.983** |
| **Recommended: Replay 0.1 vs Trace 1.0** | 0.789 vs **0.681** | 0.915 vs **0.983** |

**為何選 Replay λ=0.1**：跟 Trace λ=1.0 形成嚴格 **10× ratio**，且 replay 的 sweep 顯示 λ=0.1 仍在 plateau 範圍——「strong replay」是公平 representation。

### 3.2 「Llama BBQ 上 replay 跟 trace 的 \|ΔR\| 相近，trace 沒贏多少」

**Answer**：BBQ 的 baseline \|ΔR\|=0.18 已接近 noise floor，**\|ΔR\| 上空間小**。但 **Ω 軸暴露 mechanism 差異**——trace 把 Ω 從 0.93 拉到 0.98，replay 反而從 0.93 退到 0.92。這是 PRISM 預測的 mechanism evidence。

### 3.3 「Trace λ=1.0 太 aggressive，會傷 task fit」

**Answer**：Llama TruthQA 上 trace λ=1.0 給最佳 \|ΔR\| reduction（19%），對 fine-tune task 沒有 catastrophic 副作用。Eval loss trajectory 在 appendix 可佐證。（待補實驗 verify）
